# Copy and translations

## All user-facing text comes from lang/en, never from PHP or TSX
No sentence, label or word a person can read or hear is written in code. PHP reads it with `__('group.key')`; React reads it with `useTranslate()` from `@/hooks/use-translate`. This includes `aria-label`, `placeholder` and `<Head title>` - a screen reader and a browser tab are still an audience.

The bridge: `HandleInertiaRequests::TRANSLATED_GROUPS` lists the `lang/en/*.php` groups shared as the `lang` prop. Adding a lang file is two steps, and forgetting the second means every key from it renders as the key itself. `translate()` in `resources/js/lib/lang.ts` returns the key on a miss on purpose, the way Laravel's `__()` does, so a gap appears on screen instead of as a blank space.

Persist codes, never sentences. `App\Enums\SummaryError` values double as keys under `summaries.errors`, so a reason from the database becomes a sentence with no mapping table, copy can be reworded without a migration, and no old row contradicts the current release. Anything that has to vary by case (not_found deliberately does not invite a retry) varies in the lang file or in a pure helper such as `resources/js/lib/summary.ts`, which vitest can test without React.

`data-test` attributes, enum backing values and translation keys are identifiers, not copy, and stay in code. So is the application's own name, which is configuration: it comes from `APP_NAME` through the shared `name` prop, is the same in every language, and is rendered directly (`pages/home.tsx` uses it as the page's `h1`). Anything else a person reads goes through `lang/en`.

Filed against `**` rather than against `lang/**`: the rule matters most in the files that would otherwise hardcode a string, which is every file that renders anything.
